# Document 2: Technology Stack & Engineering Standards

## Project Name

# Atlas

**Version:** MVP 1.0

---

# Purpose

This document defines the official technology stack, repository structure, engineering standards, coding conventions, and development workflow for Atlas.

Every contributor, whether human or AI, **must follow this document exactly**. Consistency is more important than individual preference.

No technology should be introduced without a compelling reason.

---

# Technology Stack

Atlas is built using modern, production-ready technologies that integrate well with CockroachDB, AWS, and AI frameworks.

## Frontend

**Framework**

* Next.js 15 (App Router)

**Language**

* TypeScript

**UI**

* React 19

**Styling**

* Tailwind CSS

**Components**

* shadcn/ui

**Icons**

* Lucide React

**State Management**

* Zustand

**Data Fetching**

* TanStack Query

**Graph Visualization**

* React Flow (initial MVP)
* Cytoscape.js (future advanced graph view)

**Charts**

* Recharts

---

## Backend

**Language**

* Python 3.13+

**Framework**

* FastAPI

**Validation**

* Pydantic

**Dependency Injection**

* FastAPI Depends

**Async Runtime**

* asyncio

FastAPI is selected because it provides:

* excellent async performance
* automatic OpenAPI documentation
* strong typing
* clean architecture
* native AI ecosystem support

---

## AI Layer

**Primary Framework**

* LangGraph

Reason:
Atlas is built around long-running, stateful agents rather than simple prompt-response interactions.

LangGraph provides:

* persistent workflows
* agent orchestration
* branching execution
* retries
* checkpointing

---

**LLM Provider**

Amazon Bedrock

Primary model:

* Claude

Future support:

* Amazon Nova
* Llama
* DeepSeek
* other Bedrock-supported models

The application should never depend on a single model implementation.

---

## Database

Primary Database

CockroachDB Cloud

Responsibilities:

* operational data
* investigations
* memory
* relationships
* vectors
* audit logs
* users
* metadata

CockroachDB is the single source of truth.

---

## ORM

SQLAlchemy 2

Reasons:

* mature
* async support
* CockroachDB compatibility
* migrations
* flexibility

---

## Database Migration

Alembic

Every schema change must be version controlled.

---

## Vector Storage

CockroachDB Distributed Vector Index

No external vector database.

No Pinecone.

No Weaviate.

No Chroma.

Everything remains inside CockroachDB.

---

## Object Storage

Amazon S3

Stores:

* exported investigations
* PDFs
* screenshots
* uploaded evidence
* cached blockchain artifacts

---

## Background Jobs

AWS Lambda

Responsibilities:

* scheduled investigations
* rescoring
* graph maintenance
* embedding generation
* report generation

---

## Event Scheduling

Amazon EventBridge

Responsible for:

* recurring investigations
* periodic rescans

* scheduled alerts

---

## Authentication

Better Auth (or Auth.js if ecosystem support is preferred)

Authentication methods:

* email

## API Style

REST API

Future:

GraphQL may be added if necessary.

# Blockchain Data Layer

Atlas must support multiple providers through adapters.

Never tie the application directly to a single blockchain API.

Each provider should implement a common interface.

Examples:

* Alchemy
* Blockscout
* Etherscan APIs
* Covalent
* The Graph
* Native RPCs

Switching providers should not require changes elsewhere in the system.

# Coding Standards

Every file should follow these principles.

## Readability

Readable code is preferred over clever code.

---

## Small Functions

Each function should perform one responsibility.

Target:

20–40 lines.

---

## Strong Typing

Everything should be typed.

Avoid:

```python
Any
```

Unless absolutely necessary.

---

## Comments

Comment *why* something exists.

Do not comment obvious code.

Good:

> "Wallet clustering uses time proximity because attackers frequently split funds within minutes."

Bad:

> "Loop through wallets."

---

## Naming

Use descriptive names.

Good:

```text
investigation_summary
wallet_relationships
semantic_embedding
```

Avoid:

```text
data
temp
obj
item
```

---

# Folder Ownership

Each folder should own a single domain.

Example:

Investigation Agent

Owns:

* prompts
* tools
* workflows
* tests

It should not own database models belonging to another domain.

---

# Logging

Use structured JSON logging.

Every log should include:

* timestamp
* request ID
* investigation ID
* user ID (if available)
* service
* severity

---

# Error Handling

Never silently ignore errors.

Every failure should produce:

* reason
* context
* suggested recovery

Retry transient failures only.

---

# API Standards

Every endpoint should return:

```json
{
  "success": true,
  "data": {},
  "metadata": {}
}
```

Errors should return:

```json
{
  "success": false,
  "error": {
    "code": "",
    "message": "",
    "details": {}
  }
}
```

# Testing

Testing is required.

Use:

Backend:

* pytest

Frontend:

* Playwright
* Vitest

Every new feature should include tests where practical.

---

# Docker

Every service must run using Docker.

Provide:

* development compose file
* production compose file

No local dependency should require manual installation beyond Docker and the project toolchain.

---

# Environment Variables

Secrets must never be committed.

Use:

```text
.env.local

.env.example
```

Every required environment variable must appear in `.env.example` with placeholder values and descriptions.

---

# Security Principles

* validate all input
* sanitize prompts where appropriate
* use parameterized SQL queries
* encrypt secrets
* never expose AWS credentials
* apply least-privilege IAM roles
* audit all privileged operations

---

# AI Development Rules

When AI coding agents contribute:

They must:

* follow the repository structure
* avoid introducing duplicate libraries
* avoid unnecessary abstractions
* preserve backward compatibility
* update documentation when behavior changes
* write clear commit messages
* keep modules cohesive

They must not:

* change architecture without justification
* bypass established interfaces
* introduce breaking changes without documenting them
* add hidden dependencies
* skip validation or tests for critical functionality

---

# Performance Goals

The MVP should aim for:

* API responses under 500 ms for cached queries
* semantic search under 2 seconds
* investigation startup under 3 seconds
* support for thousands of stored investigations without architectural changes

These are targets, not hard guarantees.

---

# Definition of Done

A task is complete only when:

* code builds successfully
* tests pass
* documentation is updated if needed
* no linting errors remain
* logging is present where appropriate
* errors are handled gracefully
* the feature integrates with the existing architecture without regressions
