# Document 15: Entity Resolution Engine

## Project Name

# Atlas

**Version:** MVP 1.0

---

# Purpose

The Entity Resolution Engine is responsible for determining when multiple blockchain identities belong to the same real-world actor.

Blockchain addresses are not identities.

One person, organization, exchange, protocol, or attacker may control hundreds or even thousands of wallets across multiple chains.

The Entity Resolution Engine continuously analyzes evidence to determine whether seemingly unrelated blockchain objects should be associated with a single entity.

Its goal is not certainty.

Its goal is evidence-backed attribution with clearly defined confidence.

---

# Core Philosophy

Atlas investigates **actors**, not addresses.

A wallet is only one representation of an actor.

Over time, Atlas should build increasingly accurate identity profiles by combining evidence from investigations, graph intelligence, behavioral analysis, and historical memory.

Every attribution must remain explainable and reversible.

---

# Responsibilities

The Entity Resolution Engine is responsible for:

* identifying related wallets
* resolving duplicate entities
* linking blockchain identities
* maintaining entity profiles
* updating attribution confidence
* detecting conflicting attributions
* merging entity knowledge
* preserving attribution history

The engine never creates certainty where evidence is insufficient.

## Historical Memory

Atlas compares previous investigations and entity history before creating new entities.

---

# Confidence Model

Every attribution receives a confidence score.

Confidence depends on:

* quantity of evidence
* quality of evidence
* consistency over time
* corroborating investigations
* graph density
* semantic agreement

Confidence should never rely on one signal alone.

---

# Candidate Entities

Atlas avoids creating permanent entities too early.

Example

Investigation 1

↓

Possible Exchange Wallet

↓

Candidate Entity

↓

Investigation 2

↓

Additional Evidence

↓

Confidence Increases

↓

Investigation 3

↓

Official Entity

This reduces false attribution.

---

# Entity Profiles

Each entity maintains a living profile.

Profile fields include:

* entity ID
* name
* entity type
* description
* confidence
* known wallets
* known contracts
* supported chains
* first observed
* last verified
* investigation count
* pattern associations
* risk history

Profiles evolve over time without losing historical versions.

---

# Entity Merging

Two entities may later prove to be the same.

Example

Entity A

↓

Wallet Cluster

Entity B

↓

Treasury Cluster

↓

Evidence Appears

↓

Merge

The merge process must:

* preserve history
* preserve evidence
* preserve investigations
* redirect references
* create a merge audit record

Nothing should be silently discarded.

---

# Entity Splitting

Incorrect attributions must be reversible.

Example

Entity

↓

Wallet A

Wallet B

↓

↓

Historical records should clearly document when and why a split occurred.

# Performance Principles

The Entity Resolution Engine should:

* avoid duplicate entities
* support incremental updates
* cache frequently used profiles
* prioritize high-confidence evidence
* delay expensive comparisons until necessary

Scalability should support millions of identities.

---

# Failure Recovery

If entity resolution fails:

* preserve the investigation
* create temporary candidate entities
* retry asynchronously
* never discard collected evidence

Entity attribution should improve over time rather than blocking investigations.
