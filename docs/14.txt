# Document 14: Evidence Engine

## Project Name

# Atlas

**Version:** MVP 1.0

---

# Purpose

The Evidence Engine is responsible for ensuring that every conclusion made by Atlas is supported by verifiable evidence.

Evidence is the foundation of trust throughout the platform.

Relationships, risk scores, memory, entity attribution, pattern recognition, and AI-generated explanations must all trace back to supporting evidence.

If Atlas cannot explain **why** it reached a conclusion, that conclusion should not be treated as intelligence.

The Evidence Engine guarantees that every investigation remains transparent, reproducible, and auditable.

---

# Core Philosophy

Facts are temporary.

Evidence is permanent.

Conclusions may evolve as Atlas learns more.

Evidence should remain preserved exactly as it was observed.

Rather than asking:

> "What does Atlas believe?"

Investigators should be able to ask:

> "What evidence caused Atlas to believe this?"

---

# Responsibilities

The Evidence Engine is responsible for:

* collecting evidence
* validating evidence
* preserving evidence
* linking evidence to intelligence
* versioning evidence references
* assigning confidence to evidence
* detecting conflicting evidence
* maintaining audit history
* supporting explainable AI

The Evidence Engine does **not** decide whether evidence is true.

It records what was observed and how reliable it appears.

* decoded transactions

# Evidence Normalization

Different providers return different formats.

Atlas converts all evidence into a standardized structure.

Example

```text id="w2lm9x"
Source

↓

Raw Data

↓

Normalize

↓

Standard Evidence Object
```

Normalization simplifies downstream processing.

---

# Evidence Object

Each evidence record contains:

* evidence ID
* evidence type
* source
* blockchain
* timestamp
* provider
* raw reference
* normalized data
* metadata
* verification status
* confidence
* version

Evidence objects should be immutable after creation.

---

# Evidence Metadata

Metadata may include:

* block number
* chain ID
* transaction index
* log index
* contract address
* token address
* protocol
* investigator ID
* collection method

Metadata provides context without altering the original evidence.

---

# Evidence Validation

Validation confirms that evidence is authentic and internally consistent.

Examples:

Blockchain evidence

* transaction exists
* receipt exists
* block confirmed

Graph evidence

* referenced nodes exist
* relationship remains valid

External evidence

* source reachable
* timestamp verified
* integrity checks passed

Validation improves confidence but does not change the underlying evidence.

---

# Evidence Confidence

Each evidence item has its own confidence score.

Factors include:

* trusted provider
* blockchain confirmation depth
* corroborating evidence
* provider agreement
* successful validation

Confidence belongs to evidence, not conclusions.

---

# Evidence Versioning

Evidence is immutable.

However, references to evidence may evolve.

Example

Version 1

Wallet linked using:

Evidence A

Version 2

Wallet linked using:

Evidence A

*

Evidence B

Atlas versions the relationship, not the evidence itself.

---

# Contradictory Evidence

Atlas should never discard conflicting evidence.

Example

Evidence A

Suggests wallet belongs to Exchange X.

Evidence B

Suggests wallet belongs to Bridge Y.

Both are preserved.

The associated conclusion reflects uncertainty until further investigations provide additional support.

---

# Performance Principles

The Evidence Engine should:

* avoid duplicate storage
* normalize once
* reuse evidence references
* validate asynchronously where appropriate
* support efficient retrieval through indexing
* preserve immutability

Scalability should not compromise traceability.

---

# Failure Recovery

If evidence collection fails:

* preserve partial investigation results
* mark missing evidence
* retry collection
* record failure reason
* continue the investigation where possible

Atlas should never fabricate missing evidence.

# Guiding Principle

Evidence is the foundation of Atlas.

Memory can evolve.

Patterns can change.

Risk scores can increase or decrease.

Relationships can be refined.

Evidence remains the permanent record that allows every conclusion to be verified, challenged, or reproduced.

Without evidence, Atlas has opinions.

With evidence, Atlas has intelligence.
