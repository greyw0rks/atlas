# Document 30: Implementation Roadmap & Engineering Execution Plan

## Project Name

# Atlas

**Version:** MVP 1.0

---

# Purpose

This document converts the Atlas architecture into an actionable engineering execution plan.

Unlike previous documents that describe architecture and system design, this document focuses on building the product.

Its purpose is to define:

* implementation order
* engineering priorities
* repository milestones
* testing strategy
* deployment cadence
* delivery checkpoints
* hackathon timeline
* production readiness

Every task should move Atlas toward a usable product.

---

# Engineering Philosophy

Atlas should be built incrementally.

Every milestone must produce a working system.

Avoid building infrastructure that cannot yet be demonstrated.

The implementation order should prioritize:

1. Working software
2. Stable architecture
3. Performance
4. Optimization

Correctness always comes before optimization.

---

# Development Principles

Every new feature must satisfy the following:

* solves a real user problem
* integrates with existing architecture
* includes automated tests
* includes documentation
* emits structured logs
* supports observability
* follows coding standards

Features are complete only when they are testable.

# Phase 1 — Foundation

## Objectives

Create the engineering foundation.

Deliverables:

* Git repository
* Monorepo structure
* TypeScript configuration
* Authentication
* User management
* CockroachDB connection
* AWS infrastructure
* Docker development environment
* CI pipeline

Definition of Done:

Users can authenticate and the backend communicates with CockroachDB.

---

# Phase 2 — Core Investigation Engine

## Objectives

Implement blockchain investigation.

Deliverables:

* wallet lookup
* blockchain adapters
* investigation service
* transaction ingestion
* evidence collection
* timeline generation

Definition of Done:

A wallet investigation produces structured evidence.

---

# Phase 3 — Persistent Memory

## Objectives

Implement Atlas's defining feature.

Deliverables:

* memory engine
* embedding generation
* CockroachDB vector indexing
* semantic retrieval
* memory versioning
* historical investigations

Definition of Done:

Atlas remembers previous investigations and retrieves them semantically.

# Hackathon MVP Scope

The hackathon submission should deliberately remain focused.

Included:

* Wallet investigation
* Persistent memory
* CockroachDB vector search
* AI summaries
* Natural language chat
* Investigation reports
* AWS deployment

Excluded:

* Organization management
* Advanced monitoring
* Multi-user collaboration
* Plugin ecosystem
* Autonomous investigations

Deliver the smallest complete product.

# Demo Preparation

The hackathon demonstration should clearly show:

1. User submits a wallet.
2. Atlas investigates it.
3. Evidence is collected.
4. Memory is stored in CockroachDB.
5. User asks a follow-up question.
6. Atlas retrieves previous memory.
7. AI explains the investigation.
8. A professional report is generated.

The demonstration should emphasize persistent memory rather than generic AI chat.

# Risk Management

Major engineering risks include:

* overly broad scope
* AI latency
* blockchain indexing delays
* prompt instability
* insufficient testing
* infrastructure complexity

Mitigation strategy:

Build the smallest valuable system first.

Iterate after validation.
