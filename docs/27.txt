# Document 27: CockroachDB Data Model & Schema Design

## Project Name

# Atlas

**Version:** MVP 1.0

---

# Purpose

This document defines the logical and physical data model for Atlas using CockroachDB Cloud as the primary operational database and persistent memory layer.

The schema is designed to support:

* billions of blockchain transactions
* millions of investigations
* semantic vector search
* multi-tenant organizations
* AI memory
* graph intelligence
* enterprise collaboration

CockroachDB is the source of truth for Atlas.

Every investigation, report, memory object, entity, and AI interaction is ultimately persisted here.

---

# Design Principles

The database should be:

* normalized where appropriate
* denormalized where performance requires
* horizontally scalable
* strongly consistent
* audit-friendly
* multi-region ready
* optimized for AI retrieval
* optimized for vector search

Every table should have a single responsibility.

---

# Primary Design Goals

The schema must support:

* multi-tenancy
* immutable investigation history
* memory versioning
* semantic search
* graph relationships
* report generation
* event sourcing
* audit logging
* organization isolation

The database should continue performing efficiently as Atlas grows.

# Primary Key Strategy

Every table uses UUIDs.

Advantages:

* globally unique
* distributed generation
* multi-region safe

Business identifiers remain separate.

---

# Indexing Strategy

Primary indexes:

* IDs
* timestamps
* organization

Secondary indexes:

* wallet address
* entity
* investigation status
* blockchain
* report status

Composite indexes should match common query patterns.

---

# Vector Index Strategy

Memory embeddings use:

Distributed Vector Indexing.

Supports:

* semantic search
* nearest neighbor retrieval
* long-term AI memory

Vectors remain inside CockroachDB.

No external vector database is required.

---

# Relationship Strategy

Relationships are stored separately from entities.

Benefits:

* easier graph traversal
* simpler updates
* historical versioning

Edges remain immutable whenever possible.

---

# Soft Deletes

Critical business objects should use:

deleted_at

instead of physical deletion.

Historical intelligence must remain recoverable.

---

# Versioning

Version-controlled tables include:

* reports
* memories
* investigations
* risk assessments
* AI prompts

History is a first-class feature.

---

# Partitioning Strategy

Large tables should support partitioning by:

* blockchain
* organization
* time

This improves long-term scalability.

---

# Transactions

CockroachDB transactions should protect:

* investigation creation
* report generation
* memory updates
* graph updates
* organization changes

Related writes should succeed or fail together.

---

# Backup Strategy

Database backups include:

* schema
* vectors
* investigations
* audit logs
* reports metadata

Backups are encrypted and replicated.

---

# Performance Considerations

Optimize for:

* wallet lookups
* investigation retrieval
* semantic search
* graph traversal
* report generation

Avoid excessive joins in high-frequency queries.

---

# Guiding Principle

Atlas does not merely store blockchain data.

It stores institutional intelligence.

The schema is designed so that every investigation, every AI interaction, every graph relationship, and every memory contributes to a durable, explainable, and continuously improving intelligence platform powered by CockroachDB.
