# Document 28: API & Service Contract Specification

## Project Name

# Atlas

**Version:** MVP 1.0

---

# Purpose

This document defines every public API, internal service contract, real-time communication channel, and Machine Control Protocol (MCP) interface used throughout Atlas.

The objective is to ensure every frontend component, backend service, AI agent, and external integration communicates through stable, versioned contracts.

Implementation details may change.

The contracts should remain stable.

---

# Design Principles

Every API should be:

* versioned
* predictable
* stateless
* secure
* documented
* backwards compatible whenever possible
* easy for both humans and AI agents to consume

Consistency is more valuable than flexibility.

---

# API Categories

Atlas exposes five interface categories.

1. Public REST API

2. Internal Service APIs

3. WebSocket Events

4. MCP Tool Interfaces

5. Webhook Integrations

Each interface has a distinct purpose.

---

# API Versioning

Every endpoint includes a version.

Example

```text id="w4z9he"
/api/v1/...
```

Breaking changes require a new version.

Minor additions should remain backwards compatible.

# Standard Request Format

```json id="0rb1ql"
{
  "requestId": "uuid",
  "timestamp": "ISO-8601",
  "payload": {}
}
```

---

# Standard Response Format

```json id="xh5j7k"
{
  "success": true,
  "data": {},
  "meta": {
    "requestId": "uuid",
    "version": "v1"
  }
}
```

Every response follows the same structure.

---

# Error Format

```json id="z7t8da"
{
  "success": false,
  "error": {
    "code": "INVESTIGATION_NOT_FOUND",
    "message": "The requested investigation does not exist.",
    "details": {}
  }
}
```

Errors should be deterministic.

# Performance Principles

The API layer should:

* minimize payload size
* compress responses
* support caching
* stream AI responses
* avoid unnecessary round trips

Performance should improve without changing contracts.

---

# Security

Every endpoint should enforce:

* authentication
* authorization
* input validation
* rate limiting
* audit logging
* request tracing

Security policies apply consistently across every interface.

# Guiding Principle

The API is the contract between Atlas and everything that interacts with it.

A stable API enables reliable frontend development, third-party integrations, AI agents, enterprise automation, and future platform evolution.

The contract should outlive individual implementations.
