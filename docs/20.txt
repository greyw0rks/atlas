# Document 20: Natural Language Investigation Interface

## Project Name

# Atlas

**Version:** MVP 1.0

---

# Purpose

The Natural Language Investigation Interface is the primary interaction layer between investigators and Atlas.

Rather than requiring users to understand database schemas, blockchain APIs, SQL queries, or graph traversal, Atlas allows investigations to be conducted through natural conversation.

Users should be able to ask questions exactly as they think them.

Atlas translates those questions into coordinated actions performed by its internal intelligence systems.

The user speaks to one assistant.

Behind the scenes, dozens of specialized agents collaborate to produce the answer.

---

# Core Philosophy

Atlas should feel less like a blockchain explorer and more like a senior blockchain intelligence analyst.

Users should focus on asking questions.

Atlas should determine:

* what information is needed
* which agents should be consulted
* what investigations should run
* how results should be explained

The complexity remains inside the platform.

---

# Responsibilities

The Natural Language Investigation Interface is responsible for:

* understanding user intent
* maintaining conversational context
* translating requests into investigation plans
* coordinating internal agents
* presenting results naturally
* asking clarifying questions
* supporting follow-up investigations
* remembering investigation context
* adapting explanations to user expertise

The interface does **not** perform investigations directly.

It orchestrates them.

---

# User Interaction Model

Atlas supports conversational investigations.

Example

User:

> Investigate this wallet.

↓

Atlas performs investigation.

↓

User:

> Who funded it?

↓

Atlas reuses existing investigation.

↓

User:

> Follow the largest transfer.

↓

Atlas continues the investigation.

↓

User:

> Compare this wallet with yesterday's investigation.

Atlas understands the conversation without restarting from scratch.

# Intent Detection

Atlas identifies what the user wants.

Examples include:

Investigate wallet

Explain transaction

Compare wallets

Search entities

Follow fund flow

Analyze protocol

Summarize investigation

Generate report

Monitor wallet

Create alert

Export findings

Unknown requests should trigger clarification rather than assumptions.

---

# Context Retrieval

Before executing new work, Atlas retrieves:

* active investigation
* previous questions
* referenced wallets
* referenced entities
* investigation history
* conversation memory

The user should not need to repeat information unnecessarily.

---

# Conversation Memory

Conversation memory is separate from long-term intelligence.

It stores:

* active wallets
* active entities
* investigation goals
* pending questions
* temporary preferences

Conversation memory expires when the session ends unless explicitly promoted to long-term memory.

---

# Multi-Turn Investigations

Atlas supports continuous investigations.

Example

```text id="2kj8nf"
Investigate Wallet A.

↓

Find every bridge used.

↓

Which bridge appears most often?

↓

Who received the bridged funds?

↓

Investigate those wallets.

↓

Generate a summary.
```

Every question builds on previous work.

---

# Clarification Strategy

When ambiguity exists, Atlas should ask targeted questions.

Example

User:

> Investigate this address.

Possible interpretations:

* wallet
* contract
* ENS name

Atlas asks:

> Is this a wallet address or a smart contract?

Clarifications should minimize unnecessary interruptions.

---

Example

```text id="8tv4pc"

↓
```

The user never sees this internal planning unless debugging is enabled.

# Response Structure

Every response should contain:

Answer

Evidence Summary

Confidence

Reasoning

Suggested Follow-up Questions

Responses should remain concise unless the user requests greater detail.

---

# Suggested Follow-Up Questions

Atlas proactively recommends useful next steps.

Example

You investigated this wallet.

Suggested next questions:

* Who funded it?
* Which protocols does it use?
* Has Atlas seen this wallet before?
* Show related investigations.
* Monitor this wallet.

Suggestions improve investigator workflow.

---

# Investigation Continuation

Atlas should recognize when users continue previous work.

Example

Yesterday

> Continue yesterday's investigation.

Atlas restores relevant context when available.

# Performance Principles

The interface should:

* minimize repeated investigations
* reuse retrieved context
* maintain conversation state efficiently
* stream responses when possible
* support concurrent users
* reduce unnecessary agent invocations

Performance improvements should never compromise accuracy.

---

# Failure Recovery

If one subsystem fails:

Atlas should:

* explain what is unavailable
* return partial findings
* preserve conversation context
* retry when appropriate
* recommend alternative actions

Conversation should continue whenever possible.

---

# Security Considerations

The interface must:

* validate user permissions
* prevent prompt injection
* isolate conversation memory
* redact restricted information
* maintain audit logs
* protect investigation confidentiality

Security applies equally to natural language interactions.

---

# Future Enhancements

Future versions may include:

* voice-based investigations
* multilingual conversations
* collaborative investigations between multiple users
* real-time conversation sharing
* investigator personas
* adaptive explanations based on user expertise
* visual graph conversations
* conversational dashboard generation

These capabilities should extend the interface without changing its conversational architecture.

---

# Guiding Principle

The investigator should never need to think about databases, vector search, graph traversal, blockchain indexing, or AI orchestration.

They simply ask questions.

Atlas understands the objective, coordinates the appropriate intelligence systems, grounds every answer in evidence, and responds as a knowledgeable blockchain investigation partner.

The conversation becomes the interface to a continuously learning blockchain intelligence platform.
