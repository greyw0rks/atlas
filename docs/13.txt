# Document 13: Cross-Chain Intelligence Engine

## Project Name

# Atlas

**Version:** MVP 1.0

---

# Purpose

The Cross-Chain Intelligence Engine enables Atlas to investigate activity across multiple blockchains as if they were a single connected ecosystem.

Modern blockchain activity rarely stays on one chain.

An investigator may begin on Ethereum, discover a bridge to Base, follow funds to Arbitrum, observe a swap on Solana, and end at a centralized exchange.

Traditional blockchain explorers treat these as separate investigations.

Atlas treats them as one continuous story.

---

# Core Philosophy

People, organizations, and attackers operate across ecosystems, not within individual chains.

Atlas should investigate identities, behaviors, and fund flows rather than limiting analysis to a single blockchain.

The blockchain is a location.

The investigation follows the actor.

---

# Responsibilities

The Cross-Chain Intelligence Engine is responsible for:

* linking identities across chains
* tracking assets through bridges
* reconstructing cross-chain fund flows
* normalizing blockchain data
* identifying cross-chain behavioral patterns
* correlating investigations between ecosystems
* maintaining chain-aware intelligence
* providing a unified investigation timeline

It does **not** replace individual blockchain adapters.

Instead, it coordinates them.

Regardless of blockchain, Atlas represents activity using common concepts.

Core objects include:

* Wallet
* Asset
* Transaction
* Contract / Program
* Protocol
* Entity
* Bridge
* Investigation
* Pattern
* Relationship
* Evidence

Blockchain-specific details remain available but do not change the investigation workflow.

---

# Chain Adapters

Each blockchain is implemented as an independent adapter.

Responsibilities include:

* address validation
* transaction retrieval
* block retrieval
* event extraction
* protocol decoding
* token metadata
* chain-specific logic

The rest of Atlas communicates with adapters through a common interface.

Adding a new blockchain should require creating only a new adapter.

---

# Cross-Chain Identity Resolution

One individual may control many wallets across different chains.

Atlas attempts to identify related identities using evidence.

Signals include:

* bridge activity
* identical funding patterns
* repeated transaction timing
* shared centralized exchange deposits
* protocol usage
* investigator-confirmed associations

Identity resolution should always be probabilistic and evidence-backed.

---

# Bridge Intelligence

Bridges are among the most important sources of cross-chain intelligence.

Atlas should recognize:

* bridge deposits
* bridge withdrawals
* bridge contracts
* destination chains
* asset conversions
* transfer timing

Supported bridge examples may include:

* LayerZero
* Across
* Wormhole
* Hyperlane
* Axelar
* CCTP
* Native rollup bridges

Bridge support should remain modular.

# Failure Handling

Cross-chain investigations must tolerate incomplete information.

Examples:

* unsupported bridge
* missing destination transaction
* unavailable RPC
* delayed indexing
* incomplete traces

Atlas should preserve known evidence and mark unresolved transitions rather than abandoning the investigation.

# Performance Principles

The engine should:

* avoid duplicate blockchain requests
* cache bridge metadata
* normalize data once
* process chains independently where possible
* support parallel investigation across multiple chains
* allow incremental synchronization for monitored wallets

Performance should scale with the number of supported blockchains.

# Guiding Principle

Atlas investigates people, organizations, and behaviors—not blockchains.

Every supported network becomes another source of evidence feeding a single, unified intelligence system.

Cross-chain complexity should be handled by Atlas so investigators can focus on understanding behavior instead of navigating fragmented ecosystems.
