# Document 9: Knowledge Graph Agent

## Project Name

# Atlas

**Version:** MVP 1.0

---

# Purpose

The Knowledge Graph Agent is responsible for transforming isolated blockchain data into an interconnected intelligence network.

Traditional blockchain explorers store data as disconnected records.

Atlas stores knowledge as a living graph.

Instead of simply knowing:

> Wallet A transferred funds to Wallet B.

Atlas understands:

* who funded whom
* which bridge was used
* what protocol was involved
* what entity controls the wallet
* which investigations referenced it
* which attack patterns it belongs to
* how confidence has evolved over time

The Knowledge Graph Agent continuously builds, validates, and expands this intelligence graph.

---

# Core Philosophy

Knowledge becomes exponentially more valuable when connected.

A wallet alone has limited value.

A wallet connected to:

* exchanges
* protocols
* investigations
* attack patterns
* entities
* contracts
* bridges
* historical events

becomes actionable intelligence.

The Knowledge Graph Agent exists to build those connections.

---

# Responsibilities

The Knowledge Graph Agent is responsible for:

* creating graph nodes
* creating graph relationships
* validating proposed relationships
* merging duplicate entities
* expanding graph connections
* resolving identities
* traversing connected intelligence
* maintaining graph integrity
* discovering indirect relationships

The Knowledge Graph Agent **does not investigate wallets**.

It organizes the intelligence produced by other agents.

---

# Graph Model

Atlas uses a property graph model.

Everything is represented as either:

## Nodes

or

## Relationships

Nodes represent objects.

Relationships represent how those objects interact.

Relationships are first-class intelligence.

Each relationship stores:

* confidence
* evidence count
* source
* timestamp
* version
* status

Relationships are not simple foreign keys.

They are intelligence objects.

# Graph Construction Pipeline

Every relationship follows the same lifecycle.

```text id="0v7vke"
Relationship Proposal

↓

Validate Evidence

↓

Check Existing Graph

↓

Duplicate Detection

↓

Confidence Calculation

↓

Relationship Creation

↓

Graph Expansion

↓

Notify Memory Agent
```

No relationship should bypass validation.

---

# Relationship Validation

The Knowledge Graph Agent never accepts relationships blindly.

Every proposal must answer:

What evidence supports this?

How confident are we?

Has this relationship been observed before?

Does contradictory evidence exist?

If confidence is insufficient:

Store as:

**Unverified Relationship**

instead of confirmed.

---

# Entity Resolution

Multiple wallets may belong to the same real-world entity.

Example

```text id="9v9jlwm"
Wallet A

Wallet B

Wallet C

↓

Binance
```

The Knowledge Graph Agent determines when separate nodes should belong to the same entity.

Signals include:

* shared ownership
* exchange attribution
* deployment history
* funding relationships
* operational behavior
* verified investigations

Entity resolution should be conservative.

False merges are more harmful than missed connections.

# Traversal

Atlas should support graph traversal.

Example questions:

Show every wallet connected to this phishing campaign.

Find every protocol touched after Bridge X.

How many hops separate Wallet A from Exchange B?

Which investigations reference this entity?

Traversal should support:

* depth limits
* relationship filtering
* confidence filtering
* chain filtering

---

# Graph Integrity

The graph should remain internally consistent.

Rules include:

* no orphaned nodes
* no duplicate identifiers
* valid relationship directions
* consistent confidence values
* evidence references must exist
* deleted objects cannot retain active relationships

Integrity checks should run continuously.

# Failure Recovery

If graph construction fails:

* preserve investigation results
* queue graph update
* retry asynchronously
* avoid partial graph writes
* maintain transactional consistency

The graph enhances Atlas but should never block successful investigations.

# Guiding Principle

The Knowledge Graph Agent transforms isolated facts into connected intelligence.

It does not create knowledge.

It reveals how existing knowledge relates.

Every new node and every validated relationship makes Atlas better at understanding blockchain ecosystems, uncovering hidden connections, and accelerating future investigations.
